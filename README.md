# Context RepuTracker — ветка `qwen-develop`

Данная ветка посвящена подготовке внедрения **портала Одноклассники (ОК)** восьмым адаптером в продукт **dmiandr/context** (браузерное расширение Context RepuTracker).

---

## 📌 Текущее занятие: Составление Анкеты-OK

**Ветка:** `qwen-develop`

**Суть занятия:** составление **Анкеты-OK** (`okcom.js`) — анкеты портала Одноклассники для внедрения в продукт **dmiandr/context**. Анкета клонирует протокол семи существующих адаптеров (vk, lj, habr и др.) и заполняется **только подтверждёнными фактами** о живой разметке ok.ru.

**Правило №0:** ИИ сама не напишет ничего. Анкета заполняется только по фактам, подтверждённым живой разметкой. Нет факта — стоп и вопрос.

### Граница применимости
- Расширение работает **на десктопных браузерах** на основном домене **`ok.ru`**.
- Мобильные представления **не используются и не исследуются**.
- Домен **`m.ok.ru`** — только **запасной источник** поиска селекторов при неудаче на основном домене.

### Регламент и отчёты
- Регламент сбора v01 (ручной протокол F12): `docs/REGULATION_OK_COLLECTION_V01.md`
- Инструкция ручного (F12) поиска атомов A1–A6: `docs/INSTRUCTION_OK_ATOMS_A1_A6.md`
- Сводный анализ ОК: `docs/SUMMARY_ANALYSIS_OK.md`
- Журнал пробелов: `docs/OK_ANALYSIS_GAPS.md`
- Скрипт исследования v01: `scripts/InspectOK-DOM-v01.ps1`
- Отчётная документация: `reports/`

## 🧭 Указания для LLM-ботов (вести отчётную документацию)

Каждый LLM-бот, работающий над проектом **Анкета-OK**, обязан соблюдать:

1. **Фиксировать каждый шаг** в папке `reports/` — файл `REPORT.md` (или отдельный файл на шаг) с описанием: что сделано, какие файлы созданы/изменены, хеши коммитов.
2. **После каждого шага — коммит** с сообщением по Conventional Commits (тип: `docs:`, `feat:`, `fix:`, `chore:`).
3. **Указывать источники фактов** для каждой строки селектора в анкете (отчёт F12 / точечная проверка). Селекторы без источника в анкету не попадают.
4. **Не выдумывать данные.** Нет факта о живой разметке — пометить как «не собрано» в `OK_ANALYSIS_GAPS.md`, не подставлять гипотезы из головы.
5. **Соблюдать правило №0** и границу применимости (десктоп, `ok.ru`; мобильные представления не исследуются).
6. **Обновлять журнал пробелов** `OK_ANALYSIS_GAPS.md` и сводку `SUMMARY_ANALYSIS_OK.md` после каждого этапа.
7. **При фиаско сбора селекторов** на основном домене — допускать запасной поиск по `m.ok.ru` (без мобильных представлений) и фиксировать это в отчёте.
