## 1. Суть занятия

**Составление Анкеты-OK** — анкеты портала Одноклассники (`okcom.js`) для внедрения в продукт **dmiandr/context** (браузерное расширение Context RepuTracker). Анкета клонирует протокол семи существующих адаптеров (vk, lj, habr и др.) и заполняется только подтверждёнными фактами о живой разметке ok.ru.

**Правило №0:** ИИ сама не напишет ничего. Анкета заполняется только по фактам, подтверждённым живой разметкой. Нет факта — стоп и вопрос.

## 4. Граница применимости (важно)

- Расширение работает **на десктопных браузерах** на основном домене **`ok.ru`**.
- Мобильные представления **не используются и не исследуются**.
- Домен **`m.ok.ru`** — только **запасной источник** поиска селекторов при неудаче на основном домене.

## 6. Указания для LLM-ботов (вести отчётную документацию)

Каждый LLM-бот, работающий над проектом, обязан:

1. **Фиксировать каждый шаг** в этой папке `reports/` — файл `REPORT.md` (или отдельный файл на шаг) с кратким описанием: что сделано, какие файлы созданы/изменены, хеши коммитов.
2. **После каждого шага — коммит** с сообщением по Conventional Commits (тип: `docs:`, `feat:`, `fix:`, `chore:`).
3. **Указывать источники фактов** для каждой строки селектора в анкете (отчёт F12 / точечная проверка). Селекторы без источника в анкету не попадают.
4. **Не выдумывать данные.** Нет факта о живой разметке — пометить как «не собрано» в `OK_ANALYSIS_GAPS.md`, не подставлять гипотезы из головы.
5. **Соблюдать правило №0** и границу применимости (десктоп, `ok.ru`; мобильные представления не исследуются).
6. **Обновлять журнал пробелов** `OK_ANALYSIS_GAPS.md` и сводку `SUMMARY_ANALYSIS_OK.md` после каждого этапа.
7. **При фиаско сбора селекторов** на основном домене — допускать запасной поиск по `m.ok.ru` (без мобильных представлений) и фиксировать это в отчёте.
