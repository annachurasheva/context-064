# Инструкция: ручной (F12) поиск атомов A1–A6 для Анкеты-OK

**Статус:** РАБОЧАЯ ИНСТРУКЦИЯ (оператор-человек)
**Ветка:** qwen-develop
**Основание:** TASK-0304 (узловая) — анкета ОК = клон протокола семи адаптеров
**Источник принципа сбора:** `docs/connecting_a_new_portalinstruction.md` (ручной протокол F12)
**Правило №0:** ИИ сама не напишет ничего. Каждая строка селектора имеет источник — запись из конкретной точечной проверки F12. Нет факта — стоп и вопрос.
**Граница применимости:** десктоп, `ok.ru`; мобильные представления не исследуются. `m.ok.ru` — только запасной источник поиска селекторов при неудаче на основном домене.

## 1. Что мы ищем: недостающие атомы A1–A6

Из `docs/OK_ANALYSIS_GAPS.md` (§3) шесть первых атомов анкеты стоят без исходных данных:

| Атом | Поле анкеты | Что нужно добыть из живой разметки |
|------|-------------|-------------------------------------|
| **A1** | urls / Mark | Полный список подстрок адреса портала, по которым `location.href` считается порталом (не только `ok.ru`). |
| **A2** | ListActiveZones | Где на странице живут «зоны» (авторские сущности), по каким типам страниц ветвится обход. |
| **A3** | zone.element / caption | Базовый элемент зоны и её заголовок (capt). |
| **A4** | username + GetUserAlias | Источник имени автора: текст ссылки, href, data-атрибут. |
| **A5** | attachMenuDomElement / menuAttachBefore | Точка вставки меню: перед/после какого узла в зоне. |
| **A6** | attachBadge / attachBadgeMode | Куда вешать счётчик-бейдж: потомком (child) или соседом (after). |

> Принцип: селекторы берутся **только** из точечных проверок F12 на живых страницах ok.ru, а не из головы и не из других адаптеров (урок vk/lj — чужая вёрстка).

## 2. Принцип сбора (наследуется из `connecting_a_new_portalinstruction.md`)

1. **Только ручная проверка живого элемента.** Без автоматических «обстрелов» портала.
2. **Элемент выбирает человек.** ПКМ → «Проверить» (Inspect) → в DevTools выбранный элемент доступен как `$0`.
3. **Библиотека отвечает на вопросы «что спросить у страницы».** Точечные функции возвращают селектор, контейнер, дату, кандидатов идентичности.
4. **Проверка на 2–3 экземплярах** каждого типа страницы перед фиксацией.
5. **Один шаг — один отчёт.** Результат фиксируется стандартизированным файлом (см. §6).

---

## 3. Подготовка среды (Этап 1)

1. Открыть **Microsoft Edge** (только он).
2. Войти в ok.ru под учётной записью (headed-профиль, порты 9224/9226 при необходимости).
3. Открыть DevTools: **F12** (или ПКМ → «Проверить»).
4. Убедиться, что работает `$0`: вкладка **Elements**, кликнуть по любому элементу — внизу консоли появится `$0`.
5. Загрузить библиотеку функций из `connecting_a_new_portalinstruction.md` (§ Часть 1): скопировать JS-код целиком во вкладку **Console**, нажать Enter.
6. **Контроль:** в консоли появляется `✅ Portal Inspection Library loaded successfully!`.

## 4. Ручной сбор атомов A1–A6 (по типам страниц P0)

Порядок работы — по образцу сценариев из `connecting_a_new_portalinstruction.md`: выбрать элемент, выполнить точечные функции, сохранить отчёт.

### 4.1. A1 — urls / Mark

**Что делаем:** открываем каждый из подтверждённых типов страниц, смотрим адресную строку. Собираем полный список подстрок, по которым `location.href` считается порталом ОК.

- Перейти на профиль: `https://ok.ru/profile/<id>`.
- Перейти на группу: `https://ok.ru/group/<id>`.
- Перейти на дискуссию/комментарий: `https://ok.ru/discussions/.../<topic>/<message>`.
- Для каждого — зафиксировать в отчёте секцию `[01] PAGE` (URL, hostname, title).

**Команда в Console (обзор):**
```javascript
inspectPage()
```
**Фиксируем:** подстроки пути (`/profile/`, `/group/`, `/discussions/`) и сам домен `ok.ru`.

> Итог по A1 — это **перечень подтверждённых подстрок**, а не единственная `ok.ru`. Для `Mark` важны все маршруты, на которых расширение должно считаться активным.

### 4.2. A2 — ListActiveZones (где живут зоны)

**Что делаем:** на каждом типе страницы ищем элементы, которые являются «зонами» — авторскими сущностями (имя автора внутри комментария/поста/профиля).

- Выбрать имя автора комментария (в дискуссии).
- Выбрать имя автора поста (в группе).
- Выбрать имя пользователя в шапке профиля.

**Команды в Console (точечные):**
```javascript
getSelector($0)
findEntityCandidates($0)
findEventContainer($0)
```
**Фиксируем:** селекторы элементов зон на каждом типе страницы. Это и есть кандидаты для `ListActiveZones` — набор точек входа зон по типам страниц.

### 4.3. A3 — zone.element / caption

**Что делаем:** для выбранной зоны определяем её **базовый элемент** и **заголовок (capt)**.

- Базовый элемент = стабильный селектор самой зоны (контейнер, где живёт автор).
- capt = текст/элемент, который служит заголовком события (например, заголовок темы в дискуссиях, имя в шапке профиля).

**Команды:**
```javascript
getSelector($0)
findConversationContext($0)
```
**Фиксируем:** selector (zone.element) и заголовок (captElement/caption) на каждом типе страницы.

### 4.4. A4 — username + GetUserAlias

**Что делаем:** определяем, откуда движок берёт имя автора. Пробуем три источника по порядку и фиксируем, какой реально работает на ОК:
1. текст ссылки (отображаемое имя);
2. href (ссылка на профиль автора);
3. data-атрибуты (`data-user-id`, `data-author-id`, `data-id` и т.п.).

**Команды:**
```javascript
getSelector($0)
findEntityCandidates($0)
```
**Фиксируем:** какой источник даёт стабильное имя/идентификатор автора. По уроку vk у ОК data-атрибутов, вероятно, нет → приоритет: href → текст.

### 4.5. A5 — attachMenuDomElement / menuAttachBefore

**Что делаем:** определяем точку вставки меню — куда расширение цепляет «вход в дверцу» (перед/после какого узла в зоне).

**Команда:**
```javascript
findTriangleAnchor($0)
```
**Фиксируем:** из возвращённых якорей выбираем устойчивую точку: «после имени автора», «перед именем», «рядом с аватаром». Фиксируем селектор родителя и позицию (before/after).

> По уроку lj/vk: меню обычно вешается на аватар/имя автора. Для ОК — подтвердить, какая точка реально существует в разметке.

### 4.6. A6 — attachBadge / attachBadgeMode

**Что делаем:** определяем, куда вешать счётчик-бейдж и в каком режиме — **child** (потомком) или **after** (соседним элементом).

**Команда:**
```javascript
findTriangleAnchor($0)
```
плюс вручную в Elements посмотреть структуру родителя имени автора.

**Фиксируем:**
- есть ли у зоны удобный «контейнер имени» (элемент, в который можно вложить бейдж) → mode = child;
- или бейдж ставится рядом (после контейнера) → mode = after.

## 5. Команды библиотеки (справочно)

| Функция | Что возвращает | Какой атом |
|---------|----------------|------------|
| `inspectPage()` | обзор страницы, URL, title | A1 |
| `getSelector($0)` | CSS-путь до элемента | A2, A3, A5 |
| `findEntityCandidates($0)` | кандидаты идентичности (href, data-*) | A2, A4 |
| `findEventContainer($0)` | контейнер события | A2 |
| `findConversationContext($0)` | заголовок диалога/страницы | A3 |
| `findTriangleAnchor($0)` | точки вставки меню | A5, A6 |
| `inspectShadowRoot($0)` | наличие Shadow DOM | (фон для всех) |
| `inspectPageBehavior()` | SPA/динамика/History API | (фон для всех) |
| `saveInspection("OK_...")` | сохранить отчёт 15 секций | итог |

## 6. Формат фиксации результатов

По каждому прогону заполняется стандартизированный отчёт по 15 секциям (структура из `connecting_a_new_portalinstruction.md`):

```
[01] PAGE            — URL, hostname, title                → A1
[02] SELECTED_ENTITY — tag, id, class, selector, text      → A2, A3
[03] ENTITY_CANDIDATES — href / data-* / parent           → A4
[04] EVENT_CONTAINER — selector, reason, depth             → A2
[07] ROOT_CONTEXT    — заголовок диалога, url              → A3
[09] TRIANGLE_ANCHOR — точки вставки меню                  → A5, A6
[14] SELECTORS       — итоговые селекторы                  → все
```

> Именование: `OK_<тип страницы>_<№>.txt` (например `OK_discussion_01.txt`, `OK_profile_01.txt`, `OK_group_01.txt`).

## 8. Риски и ограничения

| Риск | Митигирование |
|------|---------------|
| Headless блокируется антиботом ОК | только headed Edge + CDP, ручной F12 |
| Селекторы — гипотезы | обязательная перепроверка на 2–3 живых страницах |
| Хэшированные классы нестабильны | предпочитать href-шаблоны и data-атрибуты (урок vk) |
| Данные по A1–A6 не собраны на всех типах | приоритет P0 (дискуссия, профиль, группа) |
