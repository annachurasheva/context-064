## Как пользоваться документом
Это ежедневная памятка ПОЛЬЗОВАТЕЛЯ (человека).
Фундамент — в других документах:
REGLAMENT-CODER.md — правила Кодера (агент не проектирует, только исполняет);
docs/tasks/TASK-NNNN.md — задачи с полями (цель, ветка, разрешено, запрещено);
docs/answers/answers/CODER-LOG.md — журнал Кодера.
При противоречии сила такая: решение проектировщика (чат + docs/tasks)
> этот документ > всё остальное.
Чат — для обсуждений. Репозиторий — для решений. Важное из чата обязано оказаться в репо.

## Роли и каналы
Проектировщик (Дельта, дизайн-чат): задания, решения, верификация raw на GitHub, приёмка хэшей.
Кодер (coder.qwen.ai): исполняет задачи, выдаёт файлы отдельными код-блоками; сам НЕ коммитит.
Пользователь (Anna-Ch): применяет файлы в VS Code, Build, коммит, пуш, тест,
передача хэшей, вердикт PASS/FAIL.

## Задачи и статусы
Задачи живут в docs/tasks/TASK-NNNN.md. Один файл = одна задача.
Нумерация последовательная, без перенумеровок. Имя файла — только TASK-NNNN.md.
Статусы: NEW → IN WORK → DONE.
Кодер работает только из задач со статусом NEW.
DONE — только после хэша коммита пользователя по этой задаче и верификации проектировщика по raw.
«Сборка зелёная у Кодера» — НЕ приёмка.

## Поля файла задачи (обязательны)
Цель (одна строка). Ветка. Разрешённые файлы (список). Запрещено (список).
Формат отдачи. Формат отчёта. Стоп-условия.
Служебная сводка проектировщика (первое сообщение сессии) повторяет:
репо, ветка, номер задачи, требование readback.

## Readback
Первый ответ Кодера на задачу — одна строка своими словами: что запрещено
и в каком формате отдаёт. Нет readback — работа не начинается.

## Коммиты
Формат: тип(область): текст [TASK-NNNN]
Типы: feat, fix, docs, style, refactor, test, chore.
Области: ext (EdgeExtension), dashboard, infra (scripts), env (.vscode), docs.
Одна задача = один коммит (или несколько с одним [TASK-NNNN]).
НЕ смешивать области: ext ≠ dashboard ≠ docs ≠ infra.
Не коммитить: node_modules/, dist/, профиль браузера, *.log (.gitignore).
Хэш появляется только после пуша; записать в файл задачи и передать проектировщику.
Чисто документный коммит без задачи может идти без [TASK-NNNN].

## Ветки
Инструкция ветку НЕ хардкодит: координату даёт проектировщик
в служебной сводке и в TASK-файле (поле «ветка»).
Сейчас: qwen-develop — рабочая для задач Кодера; main защищён,
слияние qwen-develop→main только рукой Anna-Ch.
Перед задачей проверить, где вы: git branch --show-current.
Не совпадает с задачей — СТОП и уточнить.

## Передача кода без порчи
Не копировать код из рендер-вью чата: markdown съедает подчёркивания.
Копировать из код-блоков raw или из файла в VS Code.
Файл = ровно одна копия кода. Запрещены: строки «修改后», заголовки «### Файл:»,
ограждения ```, пути файлов текстом, вторые копии, дописанные в конец.
Селекторы и regex с «_» — в коде только через String.fromCharCode(95).
Самопроверка после применения:
Get-ChildItem dashboard\src, EdgeExtension -Recurse | Select-String '修改后' → 0;
панель Problems (Ctrl+Shift+M) → 0 ошибок;
npm run build (внутри dashboard/) → проходит.

## Чтение docs/
Кодер читает docs/ только по белому списку из TASK-файла.
Всё остальное в docs/ — не читать, не цитировать, не переносить в отчёты.

## Сборка и артефакты
Расширение: исходники в EdgeExtension/, артефакт в dist/.
Дашборд: все npm-команды ТОЛЬКО внутри папки dashboard/ (монорепозиторий).

headless на ОК антибот распознаёт и блочит. Headless Edge + CDP — только на нейтральном вебе.

## Тесты и статусы
Статусы только: PASS / FAIL / BLOCKED / NOT TESTED. PASS ставит ТОЛЬКО пользователь.
Дашборд: npm run build + один взгляд + страница localhost без белого экрана.
Расширение: консоль F12 на портале с фильтром CTX; консоль SW — edge://extensions.
При FAIL работа остаётся ВНУТРИ задачи; не перескакивать.

## Запуск окружения

Расширение: edge://extensions → режим разработчика → загрузить распакованное → dist/.
Дашборд: cd dashboard → npm install (один раз) → npm run dev (http://localhost:5173).

## Где искать, если сломалось
Дашборд не собирается: вывод npm run build; «нет файла» = файл не закоммичен.
Подозрение на порчу: самопроверка из раздела «Передача кода без порчи».
Белый экран: F12 Console на localhost — первая строка ошибки и есть координата дефекта.
