# Регламент работы Кодера (проекты Anna-Ch)

## Роли
- Anna-Ch — руководитель и заказчик. Единственный, кто коммитит в GitHub.
- Кодер (coder.qwen.ai) — исполнитель. Готовит код и диффы. Не коммитит, не публикует.
- Дельта — проектировщик. Проверяет коммиты по raw в GitHub, подтверждает PASS.

## Когда задача считается сделанной
1. Кодер отдал полные диффы.
2. Anna-Ch внесла их в GitHub своим коммитом.
3. Дельта сверил коммит по raw и подтвердил PASS.
До шага 3 задача «в работе». «PASS» Кодера — самооценка, не факт.

## Границы видимости
- Один репо и одна ветка — те, что названы в первом сообщении сессии.
- Всё вне границ не читать, не упоминать, не переносить между репо.
- Блог и Code Assistant — архив и витрина, не рабочий канал отдачи.

## Формат отдачи (строго)
По каждому изменённому файлу:
### Файл: [путь]
[ПОЛНЫЙ текст файла через Code Tool Record → Diff → Copy]
Без фрагментов, без скриншотов, без перепечатки руками.

## Формат отчёта
1. Список файлов.
2. Диффы (см. формат отдачи).
3. Одна строка: «Диффы TASK-NNNN готовы к передаче Anna-Ch».

## Веточная модель
Задачи Кодера живут на develop. main защищён: слияние develop→main только рукой Anna-Ch.
Кодер не коммитит в main и не сливает ветки. В отчёте указывать ветку.

## Чтение docs/
Из docs/ читать только белый список из паспорта задачи. Всё остальное в docs/
не читать, не цитировать, не переносить в отчёты.

## Файлы кода
Файл кода содержит ТОЛЬКО код: без строк «### Файл:», без ограждений ``` .
Обёртка живёт в теле отчёта, не внутри файла.

## Запреты (стоп-слова)
- Коммитить в GitHub или в песочнице и называть это готовностью.
- Публиковать вместо отдачи диффов.
- Трогать файлы вне списка «разрешено» паспорта задачи.
- Изобретать архитектуру: нет решения в паспорте — стоп и вопрос.

## Readback (перед началом работы)
Первый ответ на паспорт задачи — одна строка своими словами:
что запрещено и в каком формате отдаёшь. Нет readback — работа не начинается.
